## Existing seams and feature contract

- `preprocess.extract_engineered_features(raw_text)` returns ordered floats directly from original bytes/text; it raises failures instead of fabricating zero vectors (`preprocess.py:421–436`). `FEATURE_NAMES` defines 40 fields and deliberately excludes source-biased `num_received_hops`/`has_date_header` (`preprocess.py:379–406`). Ratify this schema and order, rather than numeric comments in README or importance analysis.
- `cleanText(raw)` extracts decoded Subject plus nonattachment MIME text, strips script/style markup, normalizes Unicode, replaces URLs with `urltoken`, and returns normalized text (`preprocess.py:43–51`, `160–172`). `remove_stopwords(text)` uses cached English NLTK stopwords or sklearn fallback; it retains negations (`preprocess.py:60–65`, `501–508`). `tokenize_text` uses regex, not NLTK punkt (`preprocess.py:64–65`). Spell correction is a separate function and is not in the actual training path (`preprocess.py:54–57`, `train.py:110–121`).
- `_parse_email` accepts bytes/string only, uses `email.policy.compat32`, and decodes display headers with charset fallbacks while leaving MIME payload headers intact (`preprocess.py:461–494`). `_safe_decode` tries declared charset, UTF-8, Windows-1252, Latin-1, then replacement decoding (`preprocess.py:130–141`). `_get_email_body` skips attachment dispositions and named parts; it recursively traverses nested MIME and combines plain/HTML text (`preprocess.py:144–157`). Preserve uploaded raw bytes through both feature extraction and cleaning; never first decode the entire upload as UTF-8.
- Actual training extracts engineered features **before** cleaning and stopword filtering (`train.py:104–112`), optionally verb-lemmatizes when WordNet is present (`train.py:113–121`), then obtains Doc2Vec vectors (`train.py:148–149`). Scaler fits training engineered features only; inference must call `transform`, then concatenate `[Doc2Vec, scaled engineered]` (`train.py:157–165`). No existing single-message inference callable assembles this pipeline. Build a small dedicated inference adapter around these seams; do not call `training()` or depend on `vec_for_learning`'s tagged pandas collection API (`train.py:38–42`).
- Original raw corpus loaders return bytes, including exact Windows filenames with trailing dots; CSV rows can be strings or generated MIME bytes (`load_data.py:37–58`, `89–152`). Their dataset traversal, pandas, mbox splitting and global source statistics belong to training, not request handling (`load_data.py:155–245`). Dataset defaults are anchored to `load_data.py`'s directory (`load_data.py:20`), while artifact paths use the process working directory (`artifact_store.py:13–15`). Resolve a configured absolute artifact root at application startup.

## Determinism, concurrency and validation limits

- Installed gensim's `infer_vector` explicitly warns repeated calls can differ, defaults inference parameters to stored model values, and uses a seed based on Python's `hash` of joined tokens (`venv/Lib/site-packages/gensim/models/doc2vec.py:593–599`, `624–628`; `keyedvectors.py:2093–2103`). Its compiled inference helpers consume `model.random` (`doc2vec_inner.pyx:274`, `370`, `506`). A shared model is therefore not a stateless inference dependency. Pin process `PYTHONHASHSEED`, define explicit finite positive alpha/min-alpha and fixed epochs in the deployment contract, and serialize RNG state capture/reset/inference/restore under one lock or use one serialized worker. Verify repeat inputs, different request order, concurrency and process restart against the intended class behavior. No such runtime behavior was tested here.
- `train.py:139–146` constructs `Doc2Vec()` with default settings and subtracts `0.002` from both learning-rate fields on every epoch. The variable's name does not establish DBOW mode. Do not assume healthy saved inference defaults or particular mode from the name; inspect actual verified objects at later implementation validation. Changing inference policy is a documented adaptation and needs compatible validation, not a claim of historical training parity.
- Engineered extraction mutates module-global counters (`preprocess.py:408–436`); stopword resource choice is process-cached (`preprocess.py:501–508`). Treat counters as internal, protect/isolate them with serialized inference, and resolve/freeze resources at startup. No request should reset training statistics, fit a scaler, update model weights or publish artifacts.
- Existing email parser is permissive and is not an upload admission validator. It does not enforce one `.eml`, nonempty analyzable text, request-byte limits, MIME part/depth/decoded-text limits, or time budget. The URL-bombing comment has no implemented cap (`preprocess.py:213–255`). Add bounded admission before expensive parsing/inference, distinguish invalid/unsupported message errors, and never return a class for those errors. Existing feature helpers inspect URLs/attachment filenames locally; no URL fetching or attachment execution appears in the inference seams.

## Label-target evidence and quality limits

- Code explicitly preserves numeric 0/1 and states spam is not proof of phishing (`load_data.py:1–6`). `INCLUDE_SPAM=True` and label mapping place spam in class 1; SpamAssassin folder `spam`/`spam_2` maps to 1 (`load_data.py:24–28`, `79–85`, `122–125`). The selected manifest records SpamAssasin, TREC, CEAS, Enron, Ling and Nazario sources (`manifest.json:3–46`), without per-source label provenance or verified phishing-only policy.
- The observed legacy run has a **broad positive target** and lacks the evidence required by the accepted SPEC's `legit_vs_phishing` contract. Its class 1 must not be renamed `Phishing` for real MVP outputs, even with a disclaimer. E0 must establish reviewed dataset/source provenance, exclude ordinary spam and unknown positives, and certify reviewed legitimate class 0 and confirmed phishing class 1. Numeric labels, folder names, `classes_=[0,1]`, or setting `INCLUDE_SPAM=False` alone do not establish eligibility. If mixed positives contributed to training, create a separate reviewed target-specific training/evaluation release and preserve the legacy run's semantics/evidence. Clearly marked UI/API fixtures can support development while E0 is pending; they do not satisfy real model acceptance. This audit supports no target eligibility, accuracy claim, language detector, calibrated confidence, generalization claim, or model ranking (`_bmad-output/specs/spec-iap-web-application/SPEC.md`, Constraints; `model-and-inference.md`, Eligible training target).
